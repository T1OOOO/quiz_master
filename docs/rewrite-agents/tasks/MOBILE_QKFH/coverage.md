# MOBILE_QKFH — displayed-fact training coverage audit

**Scope:** read-only review of the current Flutter sources and JSON assets on 2026-10-19. This report proposes mechanisms; it makes no production change and does not treat a card label, a source caption, or display geometry as a new factual assertion.

## Finding

Every section has some local training, but no existing module makes every displayed, sourced field trainable. The reusable local-question pattern is sound only where it retains a stable entity identity, a source reference, four distinct options, and a correct option that is not made ambiguous by the same fact on another card.

The smallest complete shared mechanism is a **data-only claim-to-entity builder**. A generated record should retain stable IDs instead of using answer text as identity:

```text
atlas / entity_id / fact_id / field / prompt_ru / prompt_en /
option_entity_ids[4] / correct_entity_id / explanation_ru / explanation_en /
source_ids[]
```

For a card claim, use the bounded prompt “В карточке какой записи указано: …?” and the original Russian claim text; the answer is the entity ID. Render the current localized name, adding a stable qualifier when names repeat. Derive false options only from entities that do **not** have the same normalized `(field, value)` claim. If three such options are unavailable, emit no automatic item: add an authored item whose source IDs, wording, and distractors are reviewed. This is required for duplicate facts, common ingredients, common languages/currencies, shared founders, repeated dates, and tied statistics. Validate the source IDs at load time and present the source link in feedback.

This keeps a source-backed fact a source-backed fact, avoids inferring a new claim from prose, and permits complete coverage without treating textual equality as answer identity.

## Concrete source and correctness requirements

1. **Identity:** answers are stable entity IDs (`country ISO`, constellation/star ID, entry ID, organ ID, node ID, dish ID, brand/owner ID, event/work/person ID), never a potentially duplicated display string.
2. **Evidence:** generated records copy the exact existing source IDs/URL from the displayed fact. A whole-card source may support only whole-card claims; a nested fact or variant must use its nested source IDs.
3. **Fair distractors:** deduplicate display labels in the active locale, exclude entities with the same claim, and use deterministic selection. If the required four fair candidates do not exist, record an authored exception rather than silently omitting coverage.
4. **Russian:** prompts and explanations use the Russian card claim and localized entity labels. Keep standard symbols (ISO code, IAU abbreviation, numeric coordinates) only where the card already displays them; surrounding instructional prose is Russian.
5. **Coverage inventory:** write a generated audit at build/test time that reports each displayed fact ID as `generated`, `authored`, or `exploration-only`. “Exploration-only” is appropriate for visual geometry/media with no semantic source claim, not for a sourced text fact. The completed release gate must contain no unclassified displayed sourced fact.

## Recommended implementation order

1. Introduce the shared local fact-question DTO/validator and the coverage inventory, then adopt it in country, sky, music, organ, beliefs, food, brands, and knowledge without changing their canonical facts.
2. Start with country religion/source-language and organ/belief facts, since these presently show source-backed prose but have the clearest structured source links.
3. Add the narrower module builders above and review duplicate/ambiguous exceptions before enabling them in Russian mobile rounds.
4. Keep source captions and visual-only geometry separate from question content. A source label itself is not a quiz fact.

This is an audit and implementation recommendation. It does not claim source review, answer review, UI integration, mobile release, or publication acceptance.
