## Required behavior

1. Add `POST /v1/guests` with a closed JSON body containing only a nonblank `display_name`. Return a closed response containing participant ID/kind/display name, the opaque bearer token and expiry metadata. The raw token may occur only in this successful creation response and client memory; database storage remains digest-only. Reject nulls, duplicates, case aliases, unknown fields, invalid UTF-8, oversize body and invalid names without echoing input. Keep the endpoint narrowly guest/bootstrap-only; full session lifecycle remains P13.
2. Add an authenticated owner-only `GET /v1/attempts/{attempt}/reveals` (or an equally narrow documented path). Before finish, return a non-leaking conflict/validation error. A stranger receives the existing indistinguishable forbidden/not-found behavior. After finish, return only reveals for questions with accepted receipts, in attempt order.
3. Each item must validate against the accepted `reveal.schema.json`: pinned quiz/question/revision, one display answer and nonempty explanation. Single choice returns ID plus public option text; multi returns stable IDs plus readable joined public text; normalized text returns only the first display variant, never the accepted-variant list. Never reveal the whole grading map.
4. Preserve current start/answer/finish/history idempotency, ownership, deadline and scoring behavior. Compose identity and attempt routes without catch-all shadowing. Add Cache-Control `no-store` to credential and reveal responses.
