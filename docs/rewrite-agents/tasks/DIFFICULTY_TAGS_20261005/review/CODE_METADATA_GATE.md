## Actionable findings

1. **[P1] Every real API catalog is rejected by Flutter.** `next/server/internal/attempts/service.go:108` adds `difficulty_counts`; Service.Catalog at line 116 and SQLite Catalog in `next/server/internal/sqlite/attempts.go:111` always populate a nonempty four-band map. `next/apps/quiz_app/lib/api_models.dart:517` admits only bundle_version, bundle_sha256 and quiz. Trigger: any real GET /v1/catalog, including the unfiltered legacy entry. Consequence: FormatException/invalid_response prevents starting play. Small fix: extend the closed API Catalog DTO with validated optional counts (or remove the uncontracted API field); test a real Go-shaped JSON response, not the old mock. Preserve rejection of private fields.

2. **[P1] The default PostgreSQL API cannot perform difficulty selection.** `next/server/internal/httpapi/attempts.go:55` requires CatalogForDifficulty plus three StartDifficulty methods in one capability assertion; `next/server/internal/attempts/service.go` implements none. GET with quiz_id+difficulty and POST with difficulty therefore take the unsupported branch (lines 76 and 134) and return validation_failed, even for a valid nonempty band. Lead confirmed the frozen contract includes PostgreSQL. Small fix: implement the same filter-before-partition capability on Service, retaining original bundle identity and stored grading, with provider-parity tests.

3. **[P1] Whole-pack Flutter entry sends an API-invalid practice request.** `next/apps/quiz_app/lib/discovery.dart` ListTile calls `_quizLocation(pack.id, null, widget.difficulty)`; `main.dart:135` retains absent round as null. `journey.dart:199` sends practice whenever _quizId is nonnull. `next/server/internal/httpapi/attempts.go:118` / `:127` require a round for every practice request. Trigger: clicking a pack title or opening /quiz/<id> with no round, filtered or unfiltered. Consequence: the promised all-matching selection fails. Small fix: provide whole-pack practice selection in the service/HTTP path, or make the whole-pack journey explicitly use a supported mode while retaining the intended player flow; do not silently reduce all matches to round zero. Test actual request fields and handler response together.

4. **[P2] Explicit empty difficulty is treated as omission in POST.** `next/server/internal/httpapi/attempts.go:105` decodes difficulty into string and `:249` accepts empty; presence is lost. Trigger: {"difficulty":""} (with an otherwise valid body). Consequence: unfiltered selection instead of required validation_failed. Null/duplicate/case-aliased keys are already rejected by checkJSONValue, and empty GET values are rejected. Small fix: retain presence with *string/raw presence and reject an explicitly present empty string; preserve omitted-field compatibility. Add the exact empty-body negative fixture.

5. **[P2] Go dictionary validation is materially weaker than Python.** `next/server/internal/content/taxonomy.go:72-82` ignores required label_ru/label_en and aliases_ru/aliases_en and never verifies the typed prefix maps to the facet. `:140-162` validates collection predicates without checking collection IDs at all, so missing/duplicate IDs pass. Trigger: a correctly rehashed dictionary with missing labels, malformed aliases, topic:x assigned country, or repeated collection IDs. Consequence: Go import/publication accepts vocabulary Python refuses and cannot attest the frozen vocabulary gate. Small fix: mirror mandatory field/list checks, explicit prefix exceptions skill→knowledge_skill and ingredient-family→ingredient, and collection identity uniqueness. `difficulty_tags_test.go:94` is misleadingly named: it checks valid skill mapping and unsafe context, not a prefix/facet mismatch; add genuine rehashed negative dictionaries. This defect is established by complete source inspection; new Go code was not executed.

6. **[P2] A rehashed dictionary can contradict its editorial-only visibility policy.** `metadata/quiz_metadata.py:62` checks only that player_safe is boolean and `:124` trusts it; Go `taxonomy.go:224` similarly trusts PlayerSafe. Bounded independent Python reproduction changed only country:it player_safe to true, recomputed the hash, retained the existing visibility_policy, and successfully validated both dictionary and an annotation publishing country:it. Thus generated public search terms can expose the answer-country label despite the dictionary's explicit policy that country/place/cuisine/ingredient/person remain editorial-only. Small fix: enforce the declared frozen v1 facet visibility invariant in both dictionary validators, while retaining independent editorial review of whether a permitted broad context is visible in the stem/announced context. The shipped dictionary has these private flags false; this finding does not claim a current corpus leak. Flutter's namespace guard protects its question DTO but cannot remove an exposed public search label or protect other HTTP consumers.

7. **[P2] Explicit return to the library loses the selected band.** `next/apps/quiz_app/lib/journey_pages.dart:146` sends literal /library. Trigger: enter a filtered quiz then select Browse quizzes. Consequence: band is discarded contrary to back-navigation requirement. Small fix: include widget.difficulty in the library URI; next-round already correctly passes it. Add navigation coverage for this exact control.

8. **[P2] The new no_match response is not accepted by the client error DTO.** HTTP maps ErrNoMatch to 422/no_match at `next/server/internal/httpapi/attempts.go:266`; `next/apps/quiz_app/lib/api_models.dart:353` excludes that code. Trigger: a valid band with zero matches via a direct URL or stale discovery metadata. Consequence: _failure converts explicit no_match to invalid_response, hiding the useful outcome. Small fix: add no_match to the contract/client error vocabulary and show the existing empty-selection state; verify a server-shaped 422 envelope. This is separate from disabling empty bands using asset counts.
