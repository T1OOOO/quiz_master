#### P1-2: `prepare_package.py` omits `baseline/web`, `catalog.json`, `quiz-closure.json`, and baseline identity when verifying `--baseline-inputs`, weakening asset-delta lineage
- **Location:** [`prepare_package.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/prepare_package.py#L23-L32), [` prepare_package.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/prepare_package.py#L62-L68), [`release_executor.py` (`validate_asset_delta`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L193-L202)
- **Trigger:** `prepare_package.py` checks `for name in ('chart','quizzes','private'): if tree(baseline/name)!=manifest.get(name): ...` (lines 25–26), omitting `'web'`, `'catalog_sha256'`, `'quiz_closure_sha256'`, and `manifest['baseline']`. It then computes `base_web = tree(baseline/'web')` (line 62) and writes it directly to `dest/'base-web-manifest.json'` (line 67). Additionally, [`validate_asset_delta()`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L193-L202) only checks `added = set(candidate) - set(base)` against `allowlist` and does not restrict in-place modifications of existing `assets/` files in `base`.
- **Consequence:**
  1. If `baseline/web` on disk diverges from `baseline_inputs['web']`, `prepare_package.py` silently trusts `tree(baseline/'web')` as `base-web-manifest.json`, allowing unapproved files placed in `baseline/web` to be treated as baseline paths rather than `added` paths.
  2. If an existing media file under `assets/` (outside Flutter's generated manifests `assets/AssetManifest.json`, `assets/AssetManifest.bin`, `assets/AssetManifest.bin.json`, `assets/FontManifest.json`, `assets/NOTICES`) is mutated in place, it is not in `added = set(candidate) - set(base)` and bypasses `asset-delta-allowlist.json`.
  3. On the server, [`remote_script()`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L423-L431) verifies the resulting image's `/usr/share/nginx/html` against `expected['web']`, but never verifies `$base_api`'s `/usr/share/nginx/html` against `base-web-manifest.json`.
- **Smallest Adequate Correction:**
  1. In [`prepare_package.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/prepare_package.py#L25-L32), verify `tree(baseline/'web') == manifest.get('web')`, `release.sha256_file(baseline/'catalog.json') == manifest.get('catalog_sha256')`, `release.sha256_file(baseline/'quiz-closure.json') == manifest.get('quiz_closure_sha256')`, and `set(manifest.get('support', {})) == set(release.SUPPORT)`.
  2. In [`validate_asset_delta()`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L193-L202), also reject any modified paths (`{k for k in candidate if k in base and candidate[k] != base[k]}`) that are not in the fixed set of expected Flutter build outputs (`main.dart.js`, `flutter_service_worker.js`, `flutter_bootstrap.js`, `version.json`, `assets/AssetManifest.json`, `assets/AssetManifest.bin`, `assets/AssetManifest.bin.json`, `assets/FontManifest.json`, `assets/NOTICES`) unless explicitly covered by `allowlist`.

#### P1-3: `execute(..., phase="publish")` writes `reviewed-receipt.json` over SSH before checking host identity, `DEPLOY.lock`, or `>= 20%` capacity
- **Location:** [`release_executor.py` (`execute`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L642-L654)
- **Trigger:** Running `release_executor.py --execute --acknowledge-production --phase publish`.
- **Consequence:** Lines 649–651 run a separate SSH command (`umask 077; cat > /opt/quiz-master/releases/<build>/reviewed-receipt.json`) **before** invoking `remote_script()`. That first SSH mutation executes without verifying `hostname == racknerd-f0269d5`, without acquiring `flock -n 9` on `/opt/quiz-master/DEPLOY.lock`, without `test ! -e`, and without running `node_guard` (`f_bavail * 5 >= s.f_blocks`), violating the requirement for single-host/lock/capacity `>= 20%` before every server phase and no remote writes while capacity is `< 20%`.
- **Smallest Adequate Correction:** Pass the local `reviewed_receipt` content/SHA into [`remote_script()`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L310-L368) and write/compare `reviewed-receipt.json` inside the single locked SSH session **after** `hostname`, `flock -n 9`, and `node_guard` succeed.

#### P1-4: `publish` and `resume-prepare` overwrite `/opt/quiz-master/backups/<build_id>.sqlite` in place, clobbering the prepare-phase backup and invalidating recorded SQL proof hashes
- **Location:** [`release_executor.py` (`remote_script`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L329-L336), [`release_executor.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L465), [`release_executor.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L548), [`volatile_checks.py` (`record`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/volatile_checks.py#L141-L155)
- **Trigger:** `prepare` creates `/opt/quiz-master/backups/<build_id>.sqlite` (line 465) and records its SHA-256 in `sql-proof-prepare-*.json`. Later, `publish` (line 548) runs `sqlite3 "$db" ".backup '$backup'"` against the exact same path `/opt/quiz-master/backups/<build_id>.sqlite` with `backup_guard = ''`.
- **Consequence:**
  1. `publish` overwrites the existing prepare-phase backup file in place (violating no-deletions / retain-all-backups and invalidating the `backup_sha256` recorded in `sql-proof-prepare-restore-*.json` and `sql-proof-prepare-rehearsal-*.json`).
  2. If `.backup` fails mid-copy during `publish`, the prior valid backup file for `<build_id>` is destroyed.
  3. Unlike `prepare` (lines 399–405), `publish` does not check `df -B1 --output=avail /opt` before creating the backup.
- **Smallest Adequate Correction:** Use distinct immutable backup filenames per phase (e.g., `<build_id>-prepare.sqlite`, `<build_id>-publish.sqlite`, with `test ! -e` before creation) or verify and reuse in `resume-prepare` without overwriting, and update [`volatile_checks.py` (`record`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/volatile_checks.py#L141) to inspect the phase-matched backup file after checking `/opt` free bytes.

#### P2-1: `prepare_package.py` uses `git status --porcelain --untracked-files=no`, ignoring untracked files in source/build trees
- **Location:** [`prepare_package.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/prepare_package.py#L18-L19)
- **Trigger:** Untracked files present under `next/apps/quiz_app/`, `quizzes/`, `next/server/`, `next/content/`, or `deploy/helm/quiz-master/` when running `prepare_package.py`.
- **Consequence:** Both `git status --porcelain --untracked-files=no` and `git diff API_SOURCE -- quizzes next/server next/content` ignore untracked files, so untracked Dart/asset/chart files can be compiled or copied into the release candidate while `source_commit` claims a clean `HEAD`.

#### P2-2: `validate_node_status` and `validate_imagefs_blocks` in `release_executor.py` are dead code never called by `read_preflight` or `execute`, and ext4 5% reserve is not checked
- **Location:** [`release_executor.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L60-L74), [`release_executor.py` (`read_preflight`)](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L131-L161), [`test_release_executor.py`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/test_release_executor.py#L9-L13)
- **Trigger:** Calling `release_executor.py` with a preflight file showing `< 20%` free blocks (such as the current `8.33%` capacity).
- **Consequence:** [`read_preflight()`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/release_executor.py#L155-L156) only checks `deployment.get("disk", {}).get("free", 0) <= 0`. `validate_node_status()` and `validate_imagefs_blocks()` are never called anywhere in production code (only in unit test [`test_server_guards`](file:///E:/Projects/quiz_master/docs/rewrite-agents/tasks/FEEDBACK_EXECUTION_20261021/release/test_release_executor.py#L9-L10)), so `--execute` will not fail closed locally from preflight before opening an SSH connection. Additionally, neither `node_guard` nor `read_preflight` verifies that the ext4 root/imagefs 5% superuser reserve (`(f_bfree - f_bavail) / f_blocks`) remains intact.
- **Smallest Adequate Correction:** Keep `read_preflight()` permissive only for `--plan` / offline packaging if desired, but when `--execute` is set, enforce `validate_imagefs_blocks()` on the preflight payload before any SSH call, and assert `(s.f_bfree - s.f_bavail) * 20 >= s.f_blocks` (or exact reserved block count) in `node_guard`.
