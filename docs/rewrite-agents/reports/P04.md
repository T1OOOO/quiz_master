# P04 — proposed base contracts and scoring fixtures

Status: DONE (P04R final pinning evidence: `docs/rewrite-agents/reports/P04R.md`)

Scope is restricted to the proposed `quiz-contract/v1` material under `next/contracts/` and this report. No legacy application, backend, Flutter, migrations, manifests, Beads data, Git state, or live-team implementation was changed.

## Delivered contract

`next/contracts/quiz-contract/v1/` defines a private canonical draft, immutable controlled published bundle, public playable question, reveal, attempts, base room-event, and non-leaking error-envelope schema. Stable lowercase quiz/question/option IDs and a revision object (`number`, content SHA-256) are required. The published bundle carries an immutable version/hash and the controlled private grading map. Locale, source URI, optional media, explicit answer kind, and a nonnumeric `unknown` difficulty value are represented on every question. The executable fixtures cover four, five, and six options.

Draft and controlled-bundle grading are intentionally separate from pre-reveal playable DTOs. The published bundle now contains the exact immutable canonical public quiz/questions and an exactly matching private grading map. Its hash is SHA-256 of canonical UTF-8 JSON with sorted keys/compact separators and `bundle_sha256` omitted; mismatched hashes and grading maps are rejected. Public question and option shapes are closed, so `is_correct`, `correct`, `solution`, unknown aliases, grading, correct-option IDs, accepted variants, correct answers, and explanations cannot pass. Error and room validation reject those keys recursively. A reveal requires a resolved quiz/question revision and adds only a displayable `correct_answer` plus explanation. It rejects the full private text variant key.

Attempt fixtures pin the bundle version/hash, scoring-policy version, question revision, option order and position-to-option mapping; every pinned revision is compared exactly with the referenced public question. The accepted answer write binds attempt ID, participant ID, question/revision, answer payload, idempotency key/digest, UTC acceptance time, and immutable receipt. Same-key/same-payload returns that receipt; different payload conflicts. Finish history repeats a snapshot-matching question revision and receipt reference. Participant mismatch, stale snapshot revision, and missing history metadata are named rejected cases. Scores are always server-authoritative.

The base room envelope contains only session/round IDs, monotonic sequence and room version, UTC server time, audience, kind, and closed event data. Base v1 recursively rejects team IDs, captain/join/standing/score fields, immediate-correctness fields, and team event kinds, including nested data. `room-event.schema.json` explicitly reserves a separately versioned P33 extension. No P33 team admission, captain transfer, team scoring, standings, or reveal policy is represented or claimed settled here.

## Scoring and migration safety

The proposed `scoring/v1` fixtures award one point for an exact single option ID. Multiple choice awards one point only for the exact expected ID set; partial, extra, or duplicate selections score zero. Normalized text applies Unicode NFC, Unicode casefold, then Unicode-whitespace collapse/trim and matches only explicit accepted variants. Every fixture has a zero speed bonus. The server, not the client, calculates correctness and score.

P01 established that the current legacy decoder ignores checked-in `correct_answer` and retains the zero-value `correct_answer_index`. The positive legacy fixtures prove nonzero and zero source mappings are explicit, including absent/null `correct_multi` retained as `single_choice`. The isolated absent/null negatives have valid answers but invalidly classify themselves as `multiple_choice`, proving the rejection is classification—not a missing-answer side effect. Missing, negative, and out-of-range answers, unknown difficulty zero, duplicate IDs, malformed revisions, stale references, and invalid 3/7-option counts are all named rejected cases.
