## Behavior and dependencies

The strict decoder rejects unknown fields, duplicate JSON keys, trailing values,
invalid UTF-8, non-object questions and malformed required values. Legacy answer
indexes never default to zero. Null/missing/empty multi means single choice;
nonempty multi requires two unique in-range integer indexes and contains the
legacy single index. Difficulty follows the frozen unknown/1–3/4–7/8–10 mapping.
ID normalization is deterministic, collision-fatal and recorded down to every
option index. A forced import cannot hide a collision with an existing manifest.

Pinned `github.com/santhosh-tekuri/jsonschema/v6 v6.0.1` supplies actual Draft
2020-12 validation with asserted date-time format and disabled network loading.
Raw JSON is checked before typed decoding, preserving unknown-field rejection.
Cross-record validation enforces IDs, grading type/reference/coverage, normalized
text variant uniqueness, reconstructed private revisions and bundle hashes.
The root manifest lease adds only this schema validator; existing `x/text
v0.34.0` is reused and marked direct for NFC/full casefold. Its Unicode 15.0 tables
need a tested Cherokee uppercase correction; 12 cross-language vectors also pass
the P04/Python 16.0 reference. No lowercase-only substitute is used. The existing
`x/sys` version is reused for Windows atomic publication without a version change.

Hashing matches P04: compact UTF-8, sorted object keys, unescaped Unicode,
revision omitted only from its own object, bundle hash omitting only itself.
Public revisions retain private draft identities; the controlled bundle verifier
reconstructs those exact inputs. `build` requires caller-supplied version and
RFC3339 time, and rejects stale revision hashes instead of silently repairing them.

Output writes stage/sync sibling files, preflight all destinations, forbid
symlinks/traversal and refuse overwrite unless forced. Concurrent quizctl writers
are excluded. Windows uses atomic moves; POSIX no-replace publication uses a
hard link, with forced rename. Ordinary multi-file commit errors roll back;
power/process failure between final file publications is not a multi-file
transaction. The local destination must not be controlled by a hostile process.
These limits and recovery notes are explicit in `next/content/README.md`.

Diff emits quiz/question/revision identifiers and bundle hashes only. Actual
executable exits: 0 identical/success, 1 differences, 2 invalid/error. `go run`
wraps nonzero child exits, so CI requiring exact codes should build the executable.
