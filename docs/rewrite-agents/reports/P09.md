The API loads and validates one configured P08 controlled bundle before serving. PostgreSQL stores its immutable identity and private grading separately from participant attempts, public question snapshots, final typed answer receipts and finish history. Attempts pin bundle/version/hash, scoring/v1, revisions and cryptographically shuffled stable option IDs. The server owns timing and scoring. P04 response objects are validated by executable schema tests.

## Behavior

`QM_CONTENT_BUNDLE_PATH` selects the reviewed bundle. The local Home Alone default is available only for a loopback/localhost listener; other listeners require an explicit path. `QM_ATTEMPT_DURATION` defaults to 30 minutes and must be between 5 minutes and 24 hours inclusive. Startup reuses P08 raw JSON, schema, cross-record and canonical hash validation and rejects persisted bundle version/hash/content conflicts.

P05 internal participant IDs remain unchanged. Authentication supplies the internal ID; P09 reversibly exposes only `p-<32hex>` and rejects caller-supplied participant/timing/score fields. Attempt and receipt IDs use cryptographic randomness. Every answer/finish transaction locks the participant-owned attempt first. The clock is sampled after lock acquisition and uses UTC microseconds, consistently with PostgreSQL. At the deadline, new writes fail; accepted receipt replays still return the same immutable receipt, including after finish/deadline. Same-key different payload and second-key replacement both conflict.

Scores use the attempt's pinned server bundle: exact single option, exact unique multi-choice set, or P08 NFC/casefold/Unicode-whitespace text normalization. Partial multi-choice selections score zero. Finish requires at least one answer, can happen after deadline, and stores score/history atomically. Repeated and concurrent finish requests return the original result. Catalogs, snapshots, receipts and history contain no answer keys, explanations or per-answer correctness.

JSON bodies are limited to 64 KiB, must be JSON objects with the expected shape, and reject unknown fields, trailing values, duplicate/case-aliased keys, nulls, excessive nesting and invalid UTF-8. Error responses use the accepted P04 envelope and stable codes; unexpected server errors return a generic retryable 500 without the underlying error. Public DTOs use `Cache-Control: no-store`. Health/readiness and graceful shutdown remain present. Existing sessions are consumed through P05 identity service; accounts/session-creation routes are outside this packet.
