# P04R — contract pinning remediation

Status: DONE

This final remediation updates only the uncommitted P04 contract paths and P04/P04R evidence. No Git, application, manifest, legacy, Beads, or P33 change was made.

The controlled published bundle hash is now defined and checked as SHA-256 of canonical UTF-8 JSON with sorted keys and compact separators, omitting only `bundle_sha256`. Every attempt must pin that exact bundle version and digest. The published canonical public quiz/questions and private grading still must exactly match their draft counterparts.

Reveal validation now resolves the same public question revision and canonical private grading. A single-choice reveal must use the keyed option ID and its public text; normalized text may expose one explicit allowed display variant but not the complete variant key. The unanswered P33 policy—whether a team receives correctness before shared reveal—remains explicitly unresolved.

Answer writes now recompute `payload_digest` over canonical JSON of precisely attempt ID, participant ID, question ID, question revision, and typed answer; idempotency key is excluded. Attempt snapshots, writes, receipts, finish history, public DTOs, and base room/error checks retain their earlier identity/secrecy bindings. New named rejects cover attempt bundle mismatch, wrong reveal option/text, tampered digest, changed answer, and changed write revision.

The dependency-free checker executes a JSON-Schema subset (references, closed or narrowly typed objects, required/properties, types, enum/const, arrays, patterns, minimum, `not`, `anyOf`, and `oneOf`) over positive instances for all seven schemas, including the answer-write and attempt-finish definitions, then applies cross-file invariants. After review exposed that the first remediation only declared this validator without calling it, the lead performed a bounded escalation: the main path now executes the schemas, schema-valued `additionalProperties` are enforced, and every nested consumer object is closed or narrowly typed. JSON Schema validation remains deliberately bounded; P08 is responsible for a production-grade dialect validator and multi-language conformance.
