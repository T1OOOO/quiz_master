# Переход React → Flutter: обзор и поэтапная приёмка

Дата: 2026-10-02. Задача Beads: `quiz_master-0il`.
Базовая ревизия обзора: `6ec08cd`. Это дополнение к TEAM_PLAN_EN,
а не объявление завершённости старых этапов.

## Цель и ограничения

Сделать `next/apps/quiz_app` полноценной заменой React/Expo из `mobile`,
сохранив коллекцию и узнаваемый интерфейс. `flutter/` — отдельный legacy-клиент;
его наличие не доказывает готовность нового приложения.

Работать последовательно, без новых агентов, Docker, PostgreSQL и GitHub Actions.
Локальная база — SQLite. Переиспользовать импортёр, серверные попытки и имеющиеся
изображения; не создавать новый DSL, движок тем или второй формат контента.
Одна сборка/проверка за раз, ограниченная параллельность Go.

## Обзор исходников React и разрыв

Обзор выполнен по исходникам, не по живому React. Наличие обработчика/API-вызова
не доказывает работоспособность сервера. Снимки сравнения ещё не сделаны.

| Область | React: источник и поведение | Новый Flutter: разрыв |
|---|---|---|
| Каталог | `mobile/app/index.tsx`: все пакеты, дерево папок, глобальный поиск по названию/категории, хлебные крошки, параметр folder | Один пакет; вход гостя перед загрузкой; отображается технический ID |
| Карточки | `mobile/src/features/home/components/QuizListItems.tsx`: название, описание, количество, иконки, градиенты, иллюстрации, округление | Простая Material ListTile без метаданных каталога |
| Оболочка | `mobile/app/_layout.tsx`, `CustomDrawerContent.tsx`: постоянное меню от 768px, выдвижное на телефоне | AppBar с пятью отдельными переключателями языка/режима |
| Темы | `mobile/src/theme/index.ts`: Holiday, Night, Summer, Cyber, Autumn, Romance | Светлая/тёмная/системная Material-тема, единый teal |
| Прохождение | `mobile/app/quiz/[...id].tsx`, `quizStore.ts`: выбор вопроса, список статусов, повтор, перемешивание, предварительная загрузка следующих вопросов | Только последовательный переход после отправки |
| Вопрос/ответ | `QuestionCard.tsx`, `AnswerOptions.tsx`: Markdown, буквенные метки, адаптивная одна/две колонки, выделение результата | Радиокнопки/checkbox/текст; пояснение простым текстом |
| Обратная связь | React показывает пояснение сразу, автоматически переходит через 2s после верного ответа | Пояснения только после завершения попытки |
| Прогресс | `QuestionHeader.tsx`: номер, прогресс, верно/неверно, сложность /10 | Текстовый номер вопроса; нет списка и сложности в интерфейсе |
| Обратная связь автору | `quizRepository.ts`: POST /api/report, кнопка сообщения об ошибке | Нет пользовательского сценария |
| Состояние | React кеширует вопросы/summary; приёмка сохранения текущей попытки отдельно необходима | Гостевая идентичность/прохождение не восстанавливаются после перезагрузки |

Не переносить заглушки как готовые функции: React-профиль disabled «Soon»,
статистика жёстко равна нулю, logout без обработчика. Flutter `/join` пока только
admission, а не полноценная командная игра. Галерея контрактных карточек —
инструмент разработки, её нужно убрать из обычной навигации, сохранив отдельный
debug-доступ.

Не копировать недостатки React: отправку клиентского score, сравнение правильности
по тексту ответа, игнорирование ошибки каталога. Серверная оценка и стабильные ID
нового контура остаются обязательными. Автопереход должен быть отменяемым при
смене вопроса/уходе со страницы; неправильный ответ тоже не должен запирать игрока.

## Последовательные этапы

### 1. Полная проверка готовности контента

- Добавить read-only `quizctl audit --in quizzes`: рекурсивный детерминированный
  отчёт по каждому JSON, исходному и каноническому ID, названию, категории,
  числу вопросов, импортным/schema ошибкам и межпакетным коллизиям.
- Переиспользовать `content.Import` и `ValidateDraft`; не исправлять ответы,
  не публиковать bundles и не пропускать ошибочные файлы молча.
- Сохранить источник объяснений/метаданных в manifest при дальнейшем импорте.
  Missing difficulty остаётся unknown; пустой correct_multi — не multi-choice.
- Отдельно сверить все legacy-ID и нулевые/ненулевые индексы ответов с manifest;
  schema-проверка не является факт-чеком.

Приёмка: каждый файл учтён; отчёт выдаётся целиком и при ошибках; exit 2 при
блокерах; тест с дубликатами и повреждённым пакетом доказывает отсутствие тихих
пропусков/публикации. Все исходники остаются неизменными.

### 2. Полная коллекция и выбор пакета на сервере

- По результатам аудита исправлять только явно подтверждённые дефекты источников
  отдельными изменениями. Не назначать фиктивные ответы/сложность.
- После проверки целостности мигрировать пакеты существующим pipeline в приватные
  draft/manifest/bundle. Факт-чек имеет отдельный статус, не «passed» по импорту.
- Минимальный реестр пакетов и лёгкий public catalog DTO: quiz_id, revision,
  title, description, category_path, question_count; без grading и объяснений.
- `POST /v1/attempts` принимает выбранный quiz_id; неизвестный ID отклоняется.
  Заморозить bundle/manifest конкретного пакета в попытке; история показывает title.
- Не загружать все 3128 текстов в каталог. Полные вопросы — только выбранного пакета.

Приёмка: два разных пакета проходят end-to-end на SQLite; неизвестный ID,
повторная отправка, рестарт и новая версия не ломают существующие попытки.
После полного переноса числа/ID сверяются с исходниками; коллизии блокируют загрузку.

### 3. Полноценный главный экран Flutter

- Анонимный просмотр каталога до имени гостя; имя требуется при старте игры.
- Категории/подкатегории, хлебные крошки, поиск по всей коллекции с очисткой,
  URL выбранной категории и пакета, названия/описания/число вопросов.
- На телефоне 2 колонки категорий/1 викторин, на desktop 4/3 при достаточной ширине.
  Адаптировать высоту карточек к длинным русским названиям, не обрезать смысл.
- Loading/error/retry/empty состояния; не показывать неиграбельные пакеты как готовые.

Приёмка: поиск находит пакеты разных категорий; возврат сохраняет папку/поиск;
глубокая ссылка и обновление страницы корректны; проверены 390px и 1440px.

### 4. Узнаваемый дизайн и темы

- Начать с законченного Holiday: палитра, фон, шрифтовая иерархия, границы,
  радиусы, тени, иконки и иллюстрации из `mobile/assets` после проверки размера.
- Адаптивная оболочка с desktop-меню и drawer на телефоне; настройки сгруппированы.
- Затем Night, Summer, Cyber, Autumn, Romance средствами ThemeData/существующих
  провайдеров. Сохранять выбор; не загружать внешние шрифты/изображения без нужды.

Приёмка: одинаковые сценарии React/Flutter сняты на одинаковых viewport;
сравнены каталог, подкатегория, вопрос, пояснение, результат, пустой поиск и ошибка.
Нет overflow; контраст, масштаб текста и фокус клавиатуры проверены.

### 5. Навигация и карточка вопроса

- Список вопросов с answered/current состояниями, переход назад/вперёд и выбор
  номера; не разрешать изменение уже принятого ответа вопреки правилам сервера.
- Прогресс и известная сложность; unknown не превращать в «0/10».
- Markdown для stem/options/explanation, буквенные метки и адаптивная раскладка;
  медиа только по проверенным ссылкам с fallback. 4/5/6 вариантов не теряются.
- Тестировать клавиатуру, screen reader, длинные ответы и multi/text карточки.

Приёмка: возврат к вопросу сохраняет выбранный ответ, навигация не вызывает submit;
сбой сети не продвигает индекс и не теряет ввод; stable ID сохраняется при shuffle.

### 6. Учебная обратная связь и результаты

- Явно разделить practice (пояснение после ответа) и assessment/live
  (раскрытие по правилам). Режим и право reveal определяет сервер.
- После принятого ответа practice: выделение верно/неверно и пояснение,
  управляемый следующий вопрос; автопереход только при безопасном таймере.
- Повтор создаёт новую попытку, перемешивание выполняет сервер со стабильными ID.
- Итоги: название, оценка, ответы/пояснения, повтор, каталог; история с названием
  и датой вместо непрозрачного attempt ID.

Приёмка: неправильный/последний ответ, таймер, повтор и рестарт проверены;
grading не попадает в публичный каталог/незавершённый assessment.

### 7. Сохранение и обратная связь

- Сохранить guest identity, locale, theme, активную attempt ID; после reload
  восстановить состояние с сервера, не доверять сохранённому клиентскому score.
- Рабочая форма сообщения об ошибке с quiz/question/revision и текстом;
  ограничения длины, понятное подтверждение и защита endpoint от злоупотребления.
- Профиль/командный режим не маскировать заглушками: отдельные этапы после parity.

Приёмка: reload и offline→online не создают повторных ответов; форма действительно
сохраняется. Токены/приватные ответы не попадают в логи и репозиторий.

### 8. Итоговая приёмка замены

- Таблица parity с PASS/FAIL/NOT_RUN по функциям и коллекции; не заменять её
  числом зелёных unit-тестов. Старый React не удалять до прохождения приёмки.
- Полный путь каталог→поиск→пакет→ответы→пояснение→результат→история→повтор.
- Снимки desktop/mobile, автоматические проверки, локальная сборка Web;
  Android отдельно, только при доступном SDK/устройстве и ресурсе.
- Локальный браузер должен работать с обычной безопасностью: same-origin или
  ограниченный CORS, а не требовать --disable-web-security для штатного запуска.
