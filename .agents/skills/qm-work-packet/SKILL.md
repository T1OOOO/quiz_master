Read the assigned task packet, applicable AGENTS instructions and your role skill. Work only in the actual checkout and owned paths; reference repositories and pre-existing changes are not yours. A missing contract or out-of-scope file change goes to the lead before dependent edits.

Read docs/rewrite-agents/HUB_PROTOCOL_EN.md once for the hub lifecycle. Use your packet's unique hub label on every call; never inherit the server's default lead identity. Read your inbox on task start, after handoff and before reporting. Post a short start, a concrete blocker, and READY evidence; do not stream every thought. Native Codex tools manage agent lifetime; the hub carries durable communication.

Use exact source/contract pointers and targeted searches. Do not load the full team history, entire source trees, all skills or unrelated MCP schemas. Do not spawn agents. Other higher-priority applicable skill instructions still apply.

Do not change the shared git index, commit, push, switch branches or run destructive cleanup. Use scoped meaningful checks and report command, cwd, result and code revision/hashes. Tests that timed out, were skipped or could not run are incomplete. For a bug, reproduce the failing behavior before claiming a fix; trivial docs edits need no synthetic unit tests.

Return DONE, DONE_WITH_CONCERNS, NEEDS_CONTEXT or BLOCKED with changed/new files, check evidence and remaining concern. Worker DONE means ready for review, not hub acceptance or release. Hub task done waits for the real integration commit; never invent a commit. After two unsuccessful substantive fixes, report evidence and the likely missing decision instead of retrying blindly.
